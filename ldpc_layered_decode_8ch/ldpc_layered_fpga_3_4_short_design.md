# DVB-S2 Short 3/4 / Project 11/15 Layered LDPC Decoder Design

## 1. ROM 信息 / ROM Information

现有工程的 `rawData` 或 ROM 字宽为 19 bit：
The existing `rawData` / ROM word is 19 bits wide:

```text
bit18    weight      -- 行内有效/持续标志；row-active flag
bit17    pos_en      -- 原 sum_ram 静态冲突提示；old static conflict hint for sum_ram
bit16:9  pos         -- 360 并行宽字 RAM 地址；macro block address for 360-lane data
bit8:0   shift_code  -- 桶形移位控制码；barrel-shift control code
```

对于这里讨论的 DVB-S2 短帧 3/4，在本工程中按 11/15 短码处理：
For the DVB-S2 short-frame 3/4 code discussed here, named 11/15 in this project:

```text
N = 16200
K = 11880 = 33 * 360
M = 4320  = 12 * 360
q = 12
VN macro blocks = 45
CN macro layers = 12
```

MATLAB 模型中该码率的 ROM 调度表共有 312 行：
The MATLAB model uses 312 schedule rows for this rate:

```text
rows 1..156   : 正向移位调度；forward shift schedule
rows 157..312 : 反向移位调度；reverse shift schedule
```

每 13 行表示一个校验宏层，其中前 12 个槽对应最大行重 12，最后一行为 `weight=0` 的边界/flush 控制字。`pos=181` 是 dummy 边，不是真实变量节点地址。
Each 13-row group represents one check-node macro layer. The first 12 slots cover the maximum row weight of 12, and the last row with `weight=0` is a boundary/flush word. `pos=181` is a dummy edge, not a real variable-node address.

第一层示例 / Example of layer 1:

```text
1 0 1   199
1 0 9   408
1 0 10  16
1 0 12  311
1 0 13  484
1 0 22  16
1 0 28  206
1 0 33  182
1 0 181 0
1 1 181 0
1 1 181 0
1 0 45  0
0 0 34  16
```

对应的反向移位行 / Matching reverse-shift rows:

```text
1 0 1   312
1 0 9   103
1 0 10  495
...
1 0 45  112
0 0 34  495
```

新结构可以继续使用旧 ROM，但 parameter 模块应将旧字段解释为更清晰的内部调度信号：
The new structure can still use the old ROM, but the parameter module should decode it into clearer internal schedule signals:

```text
row_active = weight
edge_valid = weight and pos /= 181
row_end    = weight == 0
pos        = bit16:9
fwd_shift  = first-half shift_code
rev_shift  = second-half shift_code
msg_addr   = generated by counting edge_valid entries
```

`pos_en` 在新 APP 原位更新结构中不建议作为正确性依据。它可以保留用于调试或兼容，但真正的 RAW 冲突应由动态 bypass 解决。
`pos_en` is not recommended as a correctness mechanism in the new in-place APP update structure. It may be kept for debug or compatibility, but real RAW hazards should be handled by dynamic bypass.

## 2. 新算法 / New Algorithm

旧结构近似为 flood-like 两半程：
The old implementation is close to a two-half flood-like schedule:

```text
VNU sweep: Q = LLR + SUM - TEMP
CNU sweep: R_new = CNU(Q)
SUM accumulation: SUM += R_new
TEMP update: TEMP = R_new
```

推荐新结构为 layered 原位 APP 更新：
The recommended new implementation is a layered in-place APP update:

```text
Q       = APP_old - R_old
R_new   = CNU(Q)
APP_new = Q + R_new
R_old   = R_new
```

其中 `APP_RAM` 替代旧 `SUM_RAM` 的角色，保存当前后验值；`RMSG_RAM` 替代旧 `TEMP_RAM` 的消息存储角色，保存每条真实边的旧 C2V 消息。
`APP_RAM` replaces the old `SUM_RAM` role and stores the current posterior values. `RMSG_RAM` replaces the old `TEMP_RAM` message storage and stores old C2V messages for every real edge.

## 4. Parameter 控制器 / Parameter Controller

控制器每周期读取一条正向 ROM，同时读取或映射对应的反向 ROM：
The controller reads one forward ROM word per cycle and pairs it with the matching reverse ROM word:

```vhdl
fwd_word <= rom(addr);
rev_word <= rom(addr + 156);

row_active <= fwd_word(18);
row_end    <= not fwd_word(18);
pos        <= fwd_word(16 downto 9);
edge_valid <= fwd_word(18) and (pos /= x"B5"); -- 181
fwd_shift  <= fwd_word(8 downto 0);
rev_shift  <= rev_word(8 downto 0);
```

`msg_addr` 不建议存入 ROM，而是对真实边 `edge_valid` 计数生成：
`msg_addr` should be generated by counting real edges, instead of being stored in ROM:

```vhdl
if start_frame = '1' then
    msg_addr <= 0;
elsif edge_valid = '1' then
    msg_addr <= msg_addr + 1;
end if;
```

层计数由 13 槽 group 产生：
Layer index is generated from the 13-slot group counter:

```text
slot_cnt  = 0..12
layer_cnt = 0..11
```

## 5. 主控制时序 / Main Timing

一次迭代只扫描 156 行正向调度表，不再分 VNU sweep 和 CNU sweep 两个完整半程。
One iteration scans the 156 forward rows once; there is no separate full VNU sweep and CNU sweep.

推荐流水 / Recommended pipeline:

```text
S0 parameter read                         参数读取
S1 APP_RAM/RMSG_RAM address               发出 APP/RMSG 读地址
S2 RAM data out and bypass select          RAM 读出并选择旁路数据
S3 Q = APP - R_old                         计算 V2C 外信息
S4 saturate Q to 6 bit                     Q 饱和到 6 bit
S5/S6/S7 forward barrel shift              正向桶形移位
S8 CNU input valid                         输入 CNU
...
CNU row output after row_end/latency       CNU 行结束后输出 R_new
...
U0 delay FIFO outputs context              延迟 FIFO 输出 pos/msg_addr/rev_shift/Q_var
U1 inverse barrel shift R_new              R_new 反向桶形移位
U2 APP_new = Q_var + R_new                 计算新 APP
U3 write APP_RAM and RMSG_RAM              写回 APP/RMSG
```

CNU 必须对当前 layer 的每条真实边输出一个 `R_new`。dummy `181` 可以进入时序流保持节拍，但不得写 APP/RMSG RAM。
The CNU must output one `R_new` for each real edge in the current layer. Dummy `181` slots may remain in the timing stream, but must not write APP/RMSG RAM.

## 6. APP RAM Bypass / APP RAM 旁路

Layered 更新要求后续边读到最新 APP，因此 APP RAM 必须做动态 RAW 旁路。
Layered update requires later edges to see the newest APP value, so APP RAM needs dynamic RAW bypass.

至少实现 T-1/T-2/T-3 旁路；如果流水更深，建议做小型 pending-write CAM。
Implement at least T-1/T-2/T-3 bypass. If the pipeline is deeper, use a small pending-write CAM.

```vhdl
if pend0_we = '1' and rd_pos = pend0_pos then
    app_selected <= pend0_data;
elsif pend1_we = '1' and rd_pos = pend1_pos then
    app_selected <= pend1_data;
elsif pend2_we = '1' and rd_pos = pend2_pos then
    app_selected <= pend2_data;
else
    app_selected <= app_ram_dout;
end if;
```

当前 ROM 中的 `181` 是静态避冲突优化，可以降低冲突概率，但不能替代动态 bypass。
The existing `181` dummy entries are a static scheduling optimization. They reduce hazard probability, but cannot replace dynamic bypass.

## 7. RMSG RAM / 消息 RAM

`RMSG_RAM` 建议按真实边编号，而不是按原始 ROM 行号编号：
`RMSG_RAM` should be indexed by real-edge number, not by raw ROM row index:

```text
msg_addr = count(edge_valid)
```

位宽 / Width:

```text
360 * 6 = 2160 bit
```

深度为该码率前 156 行中 `weight=1 && pos/=181` 的真实边数。帧开始时清零。若清零开销过大，可后续增加 frame tag/valid 机制。
Depth equals the number of real edges where `weight=1 && pos/=181` in the first 156 rows. Clear it at frame start. If clear cost becomes too high, a frame tag/valid mechanism can be added later.

## 8. CNU 模块 / CNU Module

当前 MATLAB 定点模型使用：
The current MATLAB fixed-point model uses:

```text
mag_norm = floor(mag * 28 / 32)
```

如果 RTL 目标是与该 MATLAB 精确一致，CNU RTL 也应实现 `28/32`。如果继续使用旧 `ldpc_decode_processor_CNU.vhd` 中的 `31/32` 和 `24/32` 两档近似，则 MATLAB 模型也要同步修改。
If RTL must match this MATLAB model exactly, implement `28/32` in RTL. If the old two-level `31/32` and `24/32` approximation is kept, update the MATLAB model accordingly.

CNU 对每个 360 lane 计算：
For each of the 360 lanes, CNU calculates:

```text
total_sign
min1
min2
min_pos
```

然后每条边输出：
Then for each edge:

```text
use min2 if this edge is min_pos else min1
sign = total_sign xor edge_sign
```

## 9. 输出 / Output

最后一次迭代结束后，不再执行旧结构的 `LLR + SUM` 总和判决，而是直接从 `APP_RAM(1..33)` 的符号位硬判决。
After the last iteration, there is no final `LLR + SUM` pass. The hard decision directly uses the sign bits of `APP_RAM(1..33)`.

```vhdl
decoded_bit(i) <= APP_RAM(block)(11*i+10); -- sign bit
```
